# 02 – Running tests

Run from the project folder. Appium is started and stopped by the test run – don't start a separate `appium`.

## Commands

### Setup & checks

| Command | Does |
|---|---|
| `npm run setup` | Check prerequisites (Node, Java, Android SDK, adb, device) and create .env / .gitignore if missing |
| `npm run check` | Syntax-check every spec, page object, helper and tool |
| `npm run appium:doctor` | Appium UiAutomator2 doctor (JAVA_HOME, ANDROID_HOME, …) |
| `npm run appium:driver` | Install / update the UiAutomator2 driver |
| `npm run devices` | List connected Android devices |

### Tests

| Command | Does |
|---|---|
| `npm run test` | All specs |
| `npm run test:smoke` | P1 smoke – login suite + login→logout flow |
| `npm run test:regression` | Every suite |
| `npm run test:login` | Valid + invalid login |
| `npm run test:valid` | Valid login only |
| `npm run test:invalid` | Invalid login only |
| `npm run test:flow` | Login → profile → logout journey |
| `npm run test:home` | Home feed suite |
| `npm run test:profile` | Profile suite |
| `npm run test:menu` | Settings menu suite |
| `npm run test:spec` | One spec file: `npm run test:spec -- ./test/specs/home.e2e.js` |
| `npm run test:grep` | Tests whose name contains a text: `npm run test:grep -- "Edit profile"` |
| `npm run wdio` | Raw wdio runner – add your own flags |

### Reports

| Command | Does |
|---|---|
| `npm run dashboard` | Rebuild + open the dashboard |
| `npm run dashboard:build` | Rebuild the dashboard only (CI, copied runs) |
| `npm run dashboard:open` | Open the dashboard without rebuilding |
| `npm run report:allure` | Allure report of the last run (needs Java) |

### Locators & handover

| Command | Does |
|---|---|
| `npm run locators` | Live locator finder (Enter = dump screen, type a selector = test it, q = quit) |
| `npm run locators:file` | Locator JSON from a saved XML: `npm run locators:file -- path/to/screen.xml` |
| `npm run locators:catalog` | Regenerate only the locator catalogue |
| `npm run deliverables` | Regenerate this deliverables folder from the code |
| `npm run handover` | Regenerate deliverables + zip the project (no credentials) → `handover/` |

### Housekeeping

| Command | Does |
|---|---|
| `npm run clean` | Delete reports, logs and Allure results (**removes run history**) |

## Options (`.env` or in front of the command)

| Variable | Default | Effect |
|---|---|---|
| `DEVICE_NAME` | `emulator-5554` | device to use |
| `UDID` | – | pick a device when several are connected |
| `PLATFORM_VERSION` | – | e.g. `14` |
| `LOG_LEVEL` | `warn` | wdio console detail |
| `RETRIES` | `0` | re-run a failed spec file N times (each attempt shows on the dashboard) |
| `KEEP_RUNS` | `30` | runs kept in the dashboard history |
| `RUN_LABEL` | – | free text shown on the dashboard, e.g. `build 1.4.2` |
| `DENY_ALL_PERMISSIONS` | `false` | deny every Android permission popup, not only notifications |
| `IG_*` | – | test accounts – see 05-test-data |

~~~powershell
# Windows PowerShell
$env:RUN_LABEL="release check"; $env:RETRIES=1; npm run test:smoke
~~~
~~~bash
# macOS / Linux
RUN_LABEL="release check" RETRIES=1 npm run test:smoke
~~~

## During a run

1. A run id (date + time) is created → `reports/runs/<run id>/`.
2. Each spec gets a fresh app start; specs run one after another (one emulator, one account).
3. Every step: action → wait for the result → wait until the screen is still → screenshot.
4. The notification-permission popup is denied automatically whenever it appears.
5. Passwords are masked (`••••••`) in all logs and reports.
6. At the end the dashboard is rebuilt and its path printed.

## Order & state

Login and Login-to-logout start and end logged out. Home / Profile / Menu log in first if needed; Menu ends logged out.
Any order works.
