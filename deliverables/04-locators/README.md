## Strategy order used

1. **accessibility id** (`~Edit profile`) – content-desc, most stable
2. **resource-id** (`id=com.instagram.android:id/profile_tab`)
3. **UiAutomator** (`android=new UiSelector().className("android.widget.Button").description("Log in")`) – when a button and its label share a content-desc
4. **XPath via a visible label** – never by position
5. position (`.instance(3)`) – **not used**

## Rules learned on this app

- Instagram is largely React Native: often no resource-id, the label is in `content-desc`.
- Some content-descs carry data (`0followers`, `user's story, 0 of 13, Unseen.`) – use the id or match by prefix.
- Input fields have a trailing comma in content-desc (`~Password,`).
- The same prompt can come in two variants (content-desc vs text) – `notNowBtn` matches both.
- While an Android permission popup is open, the app's elements are invisible.

## Fixing a broken locator

1. Dashboard → failed step → **page source (XML)**; search for the element's text.
2. Or live: `npm run locators` → navigate on the emulator → **Enter** → `locators/screen-N.json`; type a selector to test it.
3. Update the getter in `test/pageobjects/<Page>.js` → `npm run deliverables`.
